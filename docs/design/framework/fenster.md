# UI framework – Fenster und Layout

Cards, foldable cards, tabs, menu windows, panes, dashboard (the window system itself: FRAMEWORK.md). Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-fenster.html`.

## Building blocks

- **Card** – a framed block with a head: `<section class="card"><h2 class="card-head"><x-icon name="…" />Title <form class="card-action">…</form></h2> … </section>`. Text in a card: `.card-text` (readable line length), small print `.card-note`.
- **Card head with action (task 110)** – at most one `form.card-action` at the right end of the head: an icon button (`icon-button`, tooltip) or, for the card's main action, a small button with symbol and text (`<button class="button-small"><x-icon name="refresh" />Update</button>`). Its symbols keep the button's colour. With `data-ajax` the button is busy (`is-busy`: disabled, its symbol spins) until the answer is in.
- **Karte, klappbar (foldable card, point 125, A260/A261)** – `<x-fold-card fold="ocr.mode" :title="…" icon="…" folded summary="App-eigen" summary-tone="ok">…</x-fold-card>` (slot `action` for a `form.card-action`): a card whose head ends in a chevron (`control-button card-fold-button`, `aria-expanded`, tooltip "Aufklappen"/"Zuklappen"; **rule (point 131): the chevron points down while folded = "Aufklappen" and up while open = "Zuklappen"**, every foldable section in the app follows it) that hides the body (`.card-body[hidden]`, the card gets `is-folded`). A folded card shows a short **summary** in its head (`.card-summary`, `is-ok` green check / `is-warning` warning triangle, or `summary-icon`), e.g. "App-eigen ✓", "kein Cronjob ⚠". The page sets the start state (`folded`); what a person folds is remembered **per card id** (`fold="<page>.<card>"`) in the plain cookie `dh_folds` (`core/card-fold.js`, delegated) and the **server draws that state** (`App\Http\CardFolds`), so nothing jumps on load – also in windows loaded later. `DocHamster.foldCard(card, folded)` folds from code; every toggle emits `card:fold { card, folded }`. Use it where a page has several cards and some are rarely needed; a page with one card keeps a plain card. The document detail is all foldable cards (point 185.1): Eigenschaften, GiroCode, Tags, Notiz (`detail.note`, summary = its beginning), Erkannter Text (`detail.ocr`, summary = the recognition state, its tools in an `.ocr-head` row in the body, `data-ocr-card` scopes copy/translate), Verlauf. **Compact variant (point 135):** `<x-fold-card compact …>` (`card-fold is-compact`) for sections inside a panel, e.g. the search panel: no frame, a line below, a small head; the summary shows open and folded (empty = hidden, a module may update `[data-card-summary] > span` live). `:remember="false"` (`data-card-fold-forget`) draws the page's state every time and remembers nothing – e.g. "folded unless a filter in it is set".
- **Dashboard-Baustein (Home, points 176, A349–A353)** – `dashboard/index.blade.php` (`modules/dashboard.js`, `modules/dashboard.css`): one window `kind="dashboard"` (22/60/160rem) with `<ul class="dash-grid" data-dash-grid>` of cards `<li class="card dash-widget is-s|is-m|is-l" data-widget="<type>" data-size>` (`dashboard/_widget.blade.php`, body `dashboard/widgets/<type>.blade.php`). The grid follows the window width (container `win`): one column below 34rem (phones: the widgets stack), two up to 60rem (S/M one column, L both), then six (S 2, M 3, L all). **Edit mode** only via the pencil icon button in the toolbar (`data-dash-edit`, `aria-pressed`, tooltip "Home bearbeiten" / "Bearbeiten beenden"): `.dash.is-editing` shows the "+" dropdown (`data-dash-add`, the widget types not yet shown), each widget's tool line `.dash-tools` (grip `data-dash-grip` – pointer drag or arrow keys, Escape puts back –, name, a Knopfgruppe S/M/L, X) and everything `.dash-edit-only`; every change saves at once (`POST dashboard/layout` with the widgets in order). Outside the edit mode nothing moves. Parts: `<x-empty>` (an empty widget's hint, Leerer Zustand; `.dash-empty` only in the photo field), **"Erste Schritte"** (point 213, F31: `dashboard/_first-steps.blade.php` above the grid – steps that tick themselves from the data via `App\Domain\Dashboard\FirstSteps`, each a `data-window` link to where it is done; the X hides it per person in `user_dashboards.first_steps_hidden_at`; gone by itself once all steps are done), `.dash-tiles` > `.dash-tile` (Schnellzugriff: symbol + title, an app address opens as a window, https in a new tab; X `.dash-tile-x` in edit mode), `.dash-drop` (Ablegen: a big dashed field; files go to `documents.store` without a folder = the Posteingang, the framework's `.is-drop-target` while hovered), `.dash-photo` (the person's own picture, served by an auth route only to its owner). Layout per person and organisation in `user_dashboards` (`App\Domain\Dashboard\DashboardLayout` checks every widget, size and pin). **Pinned notes widgets** (point 233, A395–A397): `DashboardLayout::PINNED` types `note_column` and `note` carry the id in `ref` (`data-ref` on the card), may exist once per id and come only from the pin on the notes board (`home/_pin.blade.php`, `.note-tool.note-pin` with `aria-pressed`, tooltip "An Home anheften" / "Von Home lösen", `modules/notes-pins.js`), never from "+". A column widget lists its notes as coloured rows linking to `notes.index?note=<id>` (the board scrolls there, `.note.is-found`); a note widget shows the text in the note's colour (`.dash-note`), editable in place through `notes.text`. Deleting the column or note takes the widget off every Home (`App\Domain\Dashboard\NotePins::forget`); moving a note keeps it.
- **Menü-Fenster (menu window, point 156, A331)** – `<x-menu-window :title :icon :url :close view="key" display="tiles|list" :entries="[…]">`: an `<x-window>` (kind `menu`) whose body lists entries, each `[href, icon, title, text, badge, count]`: icon, name, short description, red count (`badge badge-alert` with its Badges key, hidden at 0), chevron. Every entry is a `data-window` link, so a click opens the next window on the right (the window system closes the ones right of it and marks the entry as opener row). **Display:** "Liste" (rows, the description small under the name) or "Kacheln" (icon, name, two lines of description, count in the corner; a grid that follows the window width via the container `win`). Below 13rem window width only the icons stay (count on the icon, the name as tooltip); as a strip it is a normal window strip. A button group in the toolbar (list | layout-grid) switches the display of **that** window; the choice is remembered per `view` key in the cookie `dh_menu_views` (`App\Http\MenuViews`, like `CardFolds`), the module sets the default (`display`). Widths: tiles 16/36/56rem, list 12/22/28rem, priority 1. Optional slot below the entries. CSS `core/menu-window.css`, JS `core/menu-window.js`. Reference: Einstellungen (§ 5, Reference module).
- **Fenstertitel umbenennen (window title rename, points 185.2, A364)** – `<x-window :title rename-url="<POST url>" rename-field="name" :rename-data="[…]">`: a module opts in by giving the rename address (only to people with edit rights; without it the title stays plain). The `h1.win-title` gets a pencil cursor and a dotted underline on hover/focus (`tabindex="0"`); a click or Enter puts an input of the same size and font in its place (`.win-title-field`), text selected. **Enter or leaving the field saves at once** (POST `rename-data` + `rename-field` = the new name, JSON answer), **Esc or an empty/unchanged name cancels**; no ✓, no double-click. Afterwards `core/window-rename.js` retitles every open window with the same rename address (head, strip label, `data-window-title`, `aria-label`, `document.title` when active; helper `DocHamster.retitle(matches, name)`), toasts the answer's `message` and emits `DocHamster.on('window:renamed', ({ win, name, json }) => …)` so the module updates its rows. Users: the document detail (`documents.field`, `rename-field="value"`, `field=title`) and an open folder window (`folders.update` with `only_name=1` – name only, place and bank matching stay). The detail window has no name field of its own. **PO 2026-11-16:** no pencil cursor and no dotted underline any more – the title is plain text; the field comes with **✓** behind it (`.edit-field`, as click-to-edit); Enter, ✓ or leaving saves, Escape cancels.
- **Pane with drag edge (point 168.1)** – `<div class="pane" data-pane="key" style="--pane-size: var(--pane-key)">…</div><div class="pane-edge" data-pane-edge="key" role="separator" aria-orientation="horizontal" tabindex="0" aria-label="…">` (`core/pane-edge.js`, `core/pane-edge.css`): the pane is a column, its first child takes the height left. Drag the edge or use ↑/↓ (Shift = bigger steps); 12rem up to nearly the window's visible height (A424: pane – with the zoom bar as its last child – and edge still fit in the window's scroll area). Point 241, A423: a 20 px grip area with a visible grip in the middle (two short bars) and the row-resize cursor; hovered or dragged, an orange line runs across (drawn as backgrounds, since the tooltip layer hides an element's ::before/::after). A small icon button `[data-pane-reset="key"]` (symbol `restore`, tooltip "Höhe zurücksetzen") goes back to the default; a double-click on the edge does the same (edge exception). The height is remembered per **kind** (`localStorage dh.pane.<key>`, e.g. `detail` for every document detail window) and set as `--pane-<key>` on `<html>` while the script runs in `<head>`, so windows draw at their height without a jump.
- **Tabs** – switch between views of one area:
  ```blade
  <nav class="tab-bar" aria-label="Bank">
      <a class="tab" href="…" aria-current="page"><x-icon name="receipt-off" /><span>Buchungen ohne Beleg</span><span class="pill">3</span><span class="tab-mark"></span></a>
      <a class="tab" href="…"><x-icon name="link" /><span>Zugeordnete Buchungen</span><span class="pill">12</span></a>
  </nav>
  ```
  Tabs over a thin line, the active one in text colour with an orange bar (`.tab-mark`, only in the active tab) that glides to the next tab; the others quiet, darker on hover. Icon and count (`pill`) are optional. Too narrow: the bar scrolls sideways, no wrapping. Arrow keys, Home and End move between tabs. One tab bar per page (the gliding bar has one name). An empty view below shows `<p class="list-empty">…</p>`.
