# UI framework – Dokument-Bausteine

What the document window shows: properties, date, viewer, text, QR and GiroCode. Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-dokumente.html`.

## Building blocks

- **Eigenschaften-Karte (points 122.4, A252)** – the typed values of one document in its detail window (`documents/_properties.blade.php`): a **foldable card** (point 132: `<x-fold-card fold="detail.properties" class="doc-properties" :data-doc-properties="<GET url>" :data-document="<id>">`, the small quiet button "+ Eigenschaft" `data-mark-as="<id>"` in its `action` slot; the reload draws the whole card again with the remembered fold state; in the styleguide shown with the older `.doc-properties-head`) and `<ul class="prop-list">` of **property value rows** `<li class="prop-row">`: `.prop-name` (muted, fixed width) and `.prop-value` with a click-to-edit value (empty = removed). Only properties with a value show. A **suggested** value (`prop-row is-suggested`) is grey italic with `pill pill-new` "vorgeschlagen" and a ✓ (`control-button` in `form[data-prop-action]`) to confirm; the X to remove sits in `.row-actions`. A row with `data-page` + `data-box` (a value with a place) has the icon button **"Im Beleg zeigen"** (`control-button` `[data-prop-show]`, symbol `focus-2`, tooltip; point 239) before the ✓/X: a click emits `DocHamster.emit('document:highlight', { win, page, box })` (to the page, zoomed to the place, outlined briefly), hovering it emits `document:outline { win, page, box, on }` (A419: only an outline, nothing moves). Clicking into the value only edits it – the viewer never moves for that. A value typed in by hand has no place and no button. The card has **no ids** and reloads itself (JSON `{html}`) on `DocHamster.emit('properties:changed', { win, documentId })` in every window that shows the document.
- **Belegdatum-Zeile (point 214, A39)** – `documents/_doc-date.blade.php`: `<div class="doc-date" data-doc-date="<card GET url>" data-document="<id>">` at the top of the detail window's body: a `button-link` with symbol `calendar` ("Belegdatum 14.03.2026"; `is-quiet` "Belegdatum fehlt" when the document only has its upload day) that opens `DocHamster.markAs({ …, property: 'invoice_date', text })` with the Rechnungsdatum chosen; the source as a quiet `pill` (erkannt, Aufnahmedatum des Fotos, Erstelldatum der PDF); A381: a recognised date that was not taken as `field-hint doc-date-hint` with `alert-triangle`. Reloads with the properties card on `properties:changed` (JSON `date_html`).
- **Popup "Markieren als" (point 122.4)** – `DocHamster.markAs({ win, documentId, text, page, box, anchor })` (`modules/properties.js`): a framework dialog (`dialog mark-as`, built in JavaScript, with X) with the clicked text (`.mark-as-text`, orange bar), the active properties this document may carry as picked choice rows (`pick-list mark-as-list` of `label.pick-row` with a radio; second line type and current value), and a **Wert** field (`field-addon` with state symbol) that checks live on the server: `is-ok` + hint "Wird gespeichert als: …" or `is-error` + the reason; a choice shows its values as a `select`. Save stores a confirmed value (with page/box), toasts, emits `properties:changed` and resolves with the answer (null when closed). Any module may call it, e.g. from a clicked word.
- **Preview overlay (points 121.2, A240)** - `DocHamster.viewer` (`modules/document-viewer.js`) lets modules point at places on the document in the detail window: `frameIn(win)`, `page(frame)`, `goTo(frame, page)` (Promise, true when drawn), `layer(frame)` (the page element of `.doc-layer`, which zooms and pans with the picture or pdf canvas), `pointAt(frame, event)` (page-relative point), `reveal(frame, box)`, `focus(frame, box)` (point 239: zoom and pan so the box stands in the middle, at most 250 % or the present zoom), `source(frame)` (shown picture for crops); point 168.2: `init(frame)` / `release(frame)` (pdf.js for a frame added later), `scale(frame)`, `zoomBy(frame, factor, at?)`, `pan(frame, dx, dy)`, `fit(frame, 'page'|'width'|'actual')`. While a window's fullscreen viewer is open, `frameIn(win)` returns its frame, so word hover, selection and highlights follow it. Any `.detail-doc` frame directly followed by a `[data-doc-zoom]` bar is a viewer (the bar's `[data-zoom-range]` is optional). Boxes are page-relative `{x, y, w, h}` (0..1) like the OCR words. Marks: `<div class="doc-mark">` in percent of the page - semi-transparent orange with an orange frame (hover, selection), `doc-mark is-pulse` pulses briefly (`document:highlight`); `doc-mark is-faint` is lighter (a word read with low confidence, e.g. in the Live card of Texterkennung, point 124). Events: `viewer:page { frame, page }`, `viewer:box { frame, page, box, add(label, run) }` (a module adds an action to a marked area). **Zoom (point 240):** 25 % to 1000 % (A420); the slider `[data-zoom-range]` runs 0–1000 on a logarithmic scale (A421, `aria-valuetext` = percent), so 25–200 % take more than half of it; wheel, Ctrl+wheel (trackpad pinch) and two-finger pinch zoom towards the pointer or between the fingers (A422; touch in the detail window: `modules/doc-viewer-touch.js`, one finger pans only while zoomed). PDFs (`modules/doc-viewer-pdf.js`) are drawn again sharper after a zoom, but the canvas stays within 16 M device pixels and 16384 px a side – deeper zoom scales that drawing (no crash, no blank canvas).
- **Fullscreen viewer (point 168.2, A344)** – the icon button "Vollbild" (`maximize`, `[data-doc-fullscreen="<id>"]`) in the detail's zoom bar clones the window's `<template data-doc-fullscreen-tpl>` into a framework dialog `dialog-backdrop doc-fullscreen` > `dialog doc-fullscreen-box` (`modules/doc-fullscreen.js`, `modules/doc-fullscreen.css`): dark backdrop over the whole app (top layer), Esc / X / backdrop closes. It holds a `.detail-doc.doc-fullscreen-frame` + `.doc-zoom.doc-fullscreen-bar` pair, so the document viewer drives it: wheel and Ctrl+wheel zoom, drag pans, PDF pages ‹ ›, Alt+drag box. Bar (icon buttons with tooltips): ‹ › other document, title, zoom out / in (`zoom-out`, `zoom-in`, also + / −), percent, fit width (`arrow-autofit-width`), whole page (`arrow-autofit-height`, also 0), 100 % (`zoom-reset`), pages, download. Touch: one finger pans, two pinch. ← / → (and ‹ ›) open the previous / next `[data-doc]` row of the window the detail was opened from (`data-window-from`), which opens in fullscreen again; without such a list the arrows hide.
- **Turn and crop (point 238)** – icon button group `[data-doc-transform="<save url>"]` in the detail's zoom bar (same `icon-button button-small` as the other buttons there, `modules/doc-transform.js`): "Nach links drehen" (`rotate`), "Nach rechts drehen" (`rotate-clockwise`), "Zuschneiden" (`crop`, `aria-pressed`) and "Zurücksetzen" (`arrow-back-up`, only while the page shown has a rotation or crop). Every change saves at once. Non-destructive: per file and page (PDF: the page shown) a rotation (0/90/180/270, clockwise) and a crop box `[x, y, w, h]` in the original, unrotated page (0..1) – crop first, then turn (`App\Domain\Documents\PageTransform`); stored in `document_files.transform`, the file and the download stay the original. Viewer frames carry the transforms as `data-transforms` (JSON by page); the document viewer asks `DocHamster.viewer.shaper` (`size(frame, page, w, h)`, `paint(frame, page, picture)`) for the shown picture – img (`img.thumb[data-raw]`) or pdf.js canvas – and `DocHamster.viewer.refresh(frame)` shows it again after a change. The layer (`layer(frame)`) is the shown page, and OCR word boxes are stored in shown coordinates, so marks line up. Thumbnails, the receipt pack and the text recognition use the same transform. **Zuschneiderahmen**: `.crop-box` (in `.doc-layer-page`, page percent, layer `is-cropping`) with eight `.crop-handle[data-handle="nw|n|ne|e|se|s|sw|w"]` and `.crop-actions` with icon buttons ✓ (`check`, `[data-crop-apply]`, also Enter) and X (`x`, `[data-crop-cancel]`, also Esc); outside dimmed; it goes over the whole turned page; handles and buttons keep their size at any zoom. Markup from `<template data-crop-tpl>` inside the group.
- **Reading view and word pill (points 121, A241-A243)** - `<div class="ocr-read" data-ocr-read="<words url>">` (`documents/_ocr_read.blade.php`, `modules/ocr-text.js`): the recognised words laid out like on the page (monospace `.ocr-line` rows, x gaps as spaces, `.ocr-page-break` between pages). Each word is a `.word-pill` (no layout shift): `is-hover` orange tint (with the preview mark; amounts and IBANs as one group), `is-selected` stronger tint with an orange underline (never filled orange), `is-unsure` dashed underline (confidence < 60), `is-learned` dotted underline (a correction learned from this sender is offered), `is-fixed` small orange dot (corrected). Point 134: the text is never edited as a block – words are corrected one by one in the word popup; without word positions the plain text shows read-only (`p.is-plain`). A280: dragging across the words makes a normal browser text selection (Ctrl+C copies it with line breaks: words of a line by one space, lines by a line break) and shows the Auswahl-Leiste with "Kopieren" and "Markieren als …" (union box of the selected words). A281: "Alles kopieren" (`icon-button ocr-copy` `data-ocr-copy`, symbol `copy`, tooltip) at the right end of the section head copies the whole text.
- **Word popup (points 122.3, 122.7)** - a framework dialog `dialog word-popup` (built in JavaScript, with X): an enlarged crop of the spot (`.word-crop-box > canvas.word-crop`, the word framed orange), the word in a `field-addon` with live type hint (IBAN mod-97 `is-ok` / `is-error`, amount, date), notes (`.word-popup-notes`: `pill pill-warning` "unsicher erkannt", "Original: …" with "Original anzeigen" = undo, a learned suggestion with "Vorschlag nehmen") and the actions "Übernehmen" (quiet, only when changed; stores the correction) and "Markieren als …" (stores a changed correction first, then `DocHamster.markAs`). **Block (point 242):** several words give one value – Ctrl/Cmd+click adds or removes a word, Shift+click takes every word from the block's first to the clicked one in reading order (A425), letting the key go opens the popup; "+ Wort hinzufügen" (`button-quiet button-small`, symbol `plus`, under the field) lets the next tap on the document add a word (A426, phones); a marked area offers "Markieren als …" for its words (A427). A block is outlined line by line (`doc-mark is-selected`), the crop frames each line, the joined text is editable (no correction is stored for a block), "Markieren als …" passes the word indices so the server cleans the text per type (IBAN without spaces + check digits, "1 234,56" as an amount; `App\Domain\Ocr\WordBlock`, A428), grows a single IBAN group or spaced amount over the following words of its line and shows that before saving (A429), and stores the combined box as the value's place (A430). A431: a word of a recognised value (with a place) takes the whole value on hover and click; the popup names it (`word-popup-note` with `pill` "IBAN" and the value). **PO 2026-11-16:** the parts under the field stand apart – "+ Wort hinzufügen" with room above, the notes (recognised kind, learned suggestion with "Vorschlag nehmen") as one grey block, then the actions.
- **Vorschlags-Chip (point 120.4, A247)** – `<button type="button" class="suggest-chip">340,00 €</button>`, several in `<div class="suggest-chips" role="group" aria-label="…">` (optional first `<span class="suggest-chips-label">` on its own line): a value the app found that one click takes over (another amount on the document, a repaired IBAN). Dashed orange outline, never filled (it proposes; the main button decides), `aria-label`/tooltip say what the click does. A chip with `data-page` + `data-box` may show its place via `document:highlight`.
- **QR-Karte (point 120)** – `<figure class="qr-card"><img src="…svg" alt="…" width="240" height="240"><figcaption>Mit der Banking-App scannen</figcaption></figure>`: a QR code made on our server (never an external service, D-020), **always dark on white** – also in dark mode, scanners need the contrast. `qr-card is-missing` (a `div` with an icon and a `p`) stands in its place while the code can't be made and says what is missing; `is-stale` fades the code while it is redrawn.
- **GiroCode-Karte (points 120, A237–A239, A247, A249, A250)** – `documents/_girocode.blade.php` (`modules/girocode.js`, `.css`): an Eigenschaften-Karte (`detail-section doc-properties girocode`, `data-girocode="<GET url>"`, `data-document`) below the properties card, shown once the document has an IBAN or is paid. Property value rows Empfänger, IBAN, BIC, Betrag, Verwendungszweck (click-to-edit, saved as confirmed properties; an emptied Verwendungszweck is made again from invoice and customer number); a suggested amount the reader is unsure about carries `pill pill-warning` "unsicher" and the other amounts as Vorschlags-Chips; an IBAN with an OCR swap offers the repaired one as chip. Skonto: a Knopfgruppe "Voller Betrag | Mit 3 % Skonto" with a `card-note` "Zu zahlen: …". Then the QR-Karte (or `is-missing`: what is missing, or "nur Euro") and the main button "Als bezahlt markieren"; a paid document shows "Bezahlt am …" with a quiet "Rückgängig" instead. The code follows typing live (debounced GET `documents/{id}/girocode.svg?name=…&iban=…&amount=…&ref=…&skonto=1`, only drawn, nothing stored). No ids: the card reloads itself on `properties:changed` in every window that shows the document.
