# UI framework – Meldungen und Dialoge

Empty states, toasts, dialogs, Bestätigung, top layer, error log. Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-meldungen.html`.

## Building blocks

- **Leerer Zustand (empty state, point 213)** – every empty list a person meets says what goes there: `<x-empty icon="inbox" :text="__('empty.inbox')">…button…</x-empty>` (`components/empty.blade.php`, CSS `.empty-state` in `core/lists.css`): the quiet dashed `.list-empty` block with a small orange symbol, **one sentence** (what goes here, and how: "Noch keine Dokumente – hierher ziehen oder hochladen.") and, in the slot, at most one or two fitting buttons on the right (they wrap below on narrow windows). Where the window takes a drop, the sentence is the drop hint and a button is optional. Inside a `<ul>` pass `tag="li"`. Search or filters without a hit use the same block with the `search` / `filter` symbol. The upload button of an empty state is `documents/_upload-button.blade.php` (optional `folder`). Texts in `lang/*/empty.php`. Bare `.list-empty` stays for text-only notes (e.g. "not loaded yet"); Home's widgets use `<x-empty>` too (`.dash-empty` is left only for the photo field).
- **Errors are logged (point 115)** – server errors and browser errors (uncaught errors, failed promises, a module that throws inside `DocHamster.emit`) land in Einstellungen → Log, logbook "Allgemein", level error (`core/error-report.js`, at most five per page). The event bus never lets one module break another or the window system.
- **Hinweis** – `<div class="notice">…</div>`: a plain grey box with round corners for a note inside a page (e.g. a password shown once). No coloured bar on the left (PO 2026-11-16).
- **Toast** – `<div class="toast" role="status" data-toast>…</div>`: top right (on phones at the bottom), closes itself after 5 s.
- **Dialog** – `<div class="dialog-backdrop" data-dialog="name" hidden><div class="dialog" role="dialog" aria-modal="true">…</div></div>`, opened by any `[data-dialog-open="name"]` (also in windows loaded later). `data-dialog-title` on the opener sets `[data-dialog-heading]`. Close: `[data-dialog-close]`, the backdrop, Escape. Names must be unique on the page – put the record's id in them. Asking for the password happens only in the dialog "Bestätigung (Sudo)".
- **Bestätigung (Sudo, point 212, PLAN §11.1 point 6)** – sensitive actions (export, backup, Belegpaket, final delete, roles, people, upload keys, sign-ins, system update) need a confirmation from the last **five minutes**, like GitHub's sudo mode; the sign-in counts. No action has its own password field. Server: the route gets the middleware `confirmed` (`App\Http\Middleware\RequireRecentConfirmation`; the list `ROUTES` is applied at the end of `routes/web.php`, a new route may also write `->middleware('confirmed')`). Nobody without a password is asked (passkey assertion: hook in `App\Domain\Auth\RecentConfirmation::methods()`). Client: one framework dialog `dialog-backdrop[data-confirm-sudo-dialog]` ("Bitte bestätigen", password field, "Bestätigen", X) in the layout, driven by `core/confirm.js`: a **form** with `data-confirm-sudo` asks before it is sent (capture phase, before every module's own submit handler) and is then sent again with the same button (`formaction` kept); **any fetch** answered `423` + header `X-DocHamster-Confirm: required` (JSON `{confirm: true}`) asks and runs the same request again – modules need nothing for it; a plain post that arrives unconfirmed goes back with its input and opens the dialog (`confirm_required`), then a toast says to run it again. `DocHamster.confirmSudo()` → `Promise<boolean>` asks from code. Wrong password: red field frame and the reason below it.
- **Top layer (point 53)** – while shown, dialogs, dropdown panels, toasts and the tooltip lie in the browser's top layer above every window (app.js lifts them as `popover="manual"` when `hidden` goes away): never cut off at a window edge, a dialog's backdrop greys the whole app, later shown = on top. They stay in their place in the DOM, so forms, `closest('section[data-window]')` and per-window names keep working. Just toggle `hidden`; never set `popover` yourself.
- **Toast from JavaScript** – `DocHamster.toast(text, { error, undo })`: the framework toast (`error` → `toast toast-error`, red edge and dot); with `undo` a side button "Rückgängig" that calls it (8 s instead of 4 s).
