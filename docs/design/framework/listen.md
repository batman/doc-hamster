# UI framework – Listen und Daten

Rows, row actions, drag and drop, amounts, search head, filters, pager. Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-listen.html`.

## Building blocks

- **List with rows** – `<ul class="pick-list">` with `<li class="pick-row is-static">` (icon, `<span><strong>…</strong><small>…</small></span>`, optional `pill` labels and a small button on the right; the text part takes the free width, so labels and button line up at the right edge). An empty list shows the **Leerer Zustand** (below) as `<x-empty tag="li" …>`; a not yet loaded list may still show the bare `<li class="list-empty">…</li>`; an error `list-empty list-error`. A row that opens something has its link around the title (`<strong><a href="…" data-window>Name</a></strong>`): **the whole row is the click area**, nothing is underlined or orange, hover darkens the row, the keyboard shows an orange frame around it. Buttons in the row stay clickable on their own.
- **Marked row (task 110)** – one look for "this one is the current / chosen one": a raised white surface (`--mark-surface`, dark mode a lighter surface) with a light shadow (`--mark-shadow`) and the orange symbol – no bar, no border, no bold text (point 155, variant A3). Used by the current menu entry (`nav-item[aria-current="page"]`), a checked menu entry, a picked choice row (`pick-row:has(input:checked)`) and a marked list row `<li class="pick-row is-static is-marked">` (e.g. the installed version). Not for multi-select (that is `.is-selected`, orange tint). The same look marks the **opener row** of a window (`.is-opener`, set by the window system, § 5).
- **Sortable list** – (point 192: no visible grip anywhere; the handle below is hidden and shows only with the keyboard focus, the whole row drags, a long press on touch) (folder rows use the drag and drop above instead; they have no grip, point 82) `<ul class="pick-list" data-sortable>` with rows `<li class="pick-row is-static" data-id="…"><button type="button" class="pick-handle" aria-label="Verschieben"><x-icon name="grip-vertical" /></button>…</li>`. The **whole row** is the grip: with the mouse it lifts after a few pixels, with a finger after a short hold (a quick swipe still scrolls; the handle lifts at once). The row hangs on the pointer, a dashed placeholder keeps its old place (nothing jumps), an orange bar shows where it lands, near the edge the list scrolls along; on release it glides to the bar, Escape puts it back. A short click still opens the row. Keyboard on the handle: Space picks up, arrow keys move, Space drops, Escape puts back. Afterwards `DocHamster.on('list:sorted', ({ list, ids }) => …)` gets the list and the row ids in their new order; **the module saves**.
- **Row symbol (points 81, A144–A146)** – `<span class="row-icon"><x-icon … /></span>` as a row's first child: a fixed 38 px slot, so the names of all rows line up. app.js measures each symbol's own box (`getBBox`, once per symbol), sets it as a tight `viewBox` and scales the symbol to fill the slot – as tall as the two text lines (38 px) – with `vector-effect: non-scaling-stroke`, so the stroke stays 2 px. Without JavaScript it keeps its normal 24 px. Always orange (`--primary`); on a coloured row see below. (The old icon tile is gone.)
- **Inhaltszähler (content count, point 161 / F5 variant D)** – `<x-row-stats :folders="6" :documents="3" :total="50" />` as a row's second line (instead of the `small`): "6 [folder] · 3 [document] (50 [document] insgesamt)" = direct subfolders · own documents (all documents of the branch). Small inline symbols; each part has its words ("6 Ordner", "3 Dokumente", "50 Dokumente insgesamt") as tooltip and as screen-reader text. Zero parts are left out, the bracket shows only when the total differs from the own count, "Leer" only when there is nothing at all. The counts come from one grouped query for all folders of the window plus `Folder::counts()` over the tree (no N+1). Folder rows and tiles use it; the Papierkorb keeps its own count. The symbols are as tall as the digits and sit on their middle with a small even gap (point 229).
- **Eine Zeile (one line, point 224)** – `.one-line`: text ends in "…" instead of wrapping; with `data-tooltip` + `data-tooltip-overflow` the full text shows on hover only while it is cut off. Document names in the list and details views use it.
- **Auswählen (point 226)** – a `[data-pick-toggle]` button in the window's Knopfgruppe (narrow: ⋯ menu) shows the row checkboxes; remembered per browser for every folder; Ctrl/Shift picking shows them by itself; switching off drops the selection.
- **Listeneintrag (list entry, point 163)** – **one** row building block for every clickable entry: main menu `.nav-item`, dropdown and "⋯" entries `.menu-item`, menu-window entries `.menu-entry` (also the Einstellungen), window list rows `.pick-row` and `.view-list li`, and `.list-entry` for anything new. The flavours keep their class names (layout, icon size); their states are defined **once** in `core/lists.css` – never per module: **rest** no fill (in a filled list, pick rows, the row's surface: `--surface`, a coloured row its colour); **hover** one colour on every surface, the text colour at 7 % laid over the fill (`--row-tint` as a background image, so it never fights a fill; only entries that do something hover; a module row that needs a hover uses `background-image: linear-gradient(var(--row-tint), var(--row-tint))`); **focus-visible** a 2 px orange ring inside; **marked** the point-155 look (below), the hover does not change it; **disabled** (`:disabled`, `aria-disabled="true"`, `.is-disabled`) faded, no hover; **sizes** normal at least 48 px high with .85rem side padding, compact (`.is-compact`, `.view-list` rows) 36 px with .35rem .6rem. Rounded corners `--row-radius` (8 px). Styleguide: "Listeneintrag".
- **Auswahl-Leiste (point 134, A280)** - `DocHamster.selectionBar.show(rect, [{ label, icon, run }])` (`core/selection-bar.js`): a small floating toolbar `<div class="selection-bar" role="toolbar">` of quiet small buttons (`button-quiet button-small`, symbol + text) on the surface colour with a shadow, centred above a text selection (below it when there is no room). One for the whole page, in the top layer like the tooltip; it hides on `selectionBar.hide()`, Escape, scrolling, resizing and when the selection goes away, and its buttons never take the selection away. `DocHamster.copyText(text)` copies to the clipboard (Promise → false when refused). Used by the reading view ("Kopieren", "Markieren als …"); any module with selectable text may use it. **Docked (point 196):** `div.selection-bar.is-docked[data-pick-bar]` (`documents/_pick-bar.blade.php`) is the same bar for picked list rows, sticky at the bottom of its window (not in the top layer): `.selection-count` "N ausgewählt", the Ordner-Menü (`control-button` dropdown), in the Posteingang ✓ "Erledigt" (`data-pick-done`), X "Auswahl aufheben" – icon buttons with tooltip. Rows are picked by a checkbox before each row (`input.row-pick[data-pick]`, `documents/_pick`; Shift = range from the last one), Ctrl/Shift on the row, or "Alle auswählen" (`label.pick-all` / the details table's head cell `.col-pick`, `[data-pick-all]`, indeterminate while only some are picked); `modules/documents-select.js` keeps bar and checkboxes in step, `modules/documents-pick.js` runs the actions (one bulk request). Dragging a picked row carries the whole selection. Used in the Posteingang and in the list and details views of Dokumente (A369, A370).
- **Coloured row ("farbige Zeile", point 83, A156–A160)** – `class="pick-row is-static row-color c-rrggbb"` (`Folder::rowClassFor($hex)` / `$folder->rowClass()`): the record's palette colour fills the **whole row**. Text is dark (`#1f1e1d`) or white, whichever has the higher WCAG contrast; the second line is that colour, faded; the symbol stays orange while orange reaches 3:1 against the row, else it takes the text colour. The classes come from `tags.css` like the palette classes (`PaletteColor::cssRule()` adds `--row-bg`, `--row-ink`, `--row-sub`, `--row-icon`), so the CSP needs no inline styles; every colour of the palette, of a folder and of the Papierkorb gets its class. Folders use it now, tags may later.
- **Row actions ("Zeilen-Aktionen", A161–A166, A174, A177)** – `<span class="row-actions">` at the right end of a row with frameless `control-button`s and tooltips: **pencil** = rename in place, **gear** = open the properties (folder) as a module to the right (`data-window` link); document rows have no gear – the whole row opens the document (point 167, below). Shown while the row is hovered or has focus, always on touch screens (`@media (hover: none)`), orange on hover. Used by folder rows, the Papierkorb row and document rows (`documents/_row-actions.blade.php`; in a table a last cell `td.row-actions-cell`); other lists (tags, members, palette) take it over instead of a ⋯ menu. A row never has a ⋯ menu any more.
- **Row that opens as a whole (point 167)** – `data-doc-row tabindex="0"` on a document row (`li`/`tr`): a click anywhere on it, or Enter while it has the focus, clicks its title `a[data-window]` (given `tabindex="-1"`, so the row is the only tab stop); links, buttons, fields, forms and `.row-actions` keep their own action, Ctrl/Shift still pick rows (`modules/documents-rows.js`). Document rows in the Liste view are `pick-row is-static doc-row` like folder rows: orange file-type symbol in the `row-icon` slot, title, second line `row-stats` (date · size · pages · small tags); the title link stretches over the row.
- **Rename in place (row, A188–A190)** – one rule for folder and document rows: the pencil turns the name into a small field with a **✓** right of it (no X). **Enter or ✓ saves** in the background (JSON, toast), **Escape or a click anywhere outside the row cancels**; leaving the field with Tab keeps it open. Folder rows hold a hidden `form[data-folder-rename-form]` (an `input-small` plus the ✓ submit), the pencil is `data-folder-rename`; document rows: the pencil `data-doc-rename="<documents.field url>"` (with `data-save` = the ✓ label) builds `.doc-rename` (field + ✓) in place of `[data-doc-title]` (`field=title`). **Long press on the name** (`[data-folder-name] strong` / `[data-doc-title]`, only the text itself) starts the same rename: about **2 s with the mouse, 1 s with a finger**; meanwhile a thin orange line fills under the name (`.is-pressing`, `.is-touch`). Released earlier: nothing happens, a short click still opens the row; moving cancels it (with the mouse a drag starts after 5 px as usual; a finger on the name doesn't lift the row by holding); the click that ends a long press neither opens the row nor starts a drag. While renaming the row's actions hide (`.is-renaming`). Afterwards the new name follows at once in every open window (rows, heads, strips).
- **Picking several rows (A132)** – document rows carry `data-doc="<id>"` (and `data-folder`, `data-trashed` in the Papierkorb): Ctrl/⌘-click adds or removes one, Shift-click picks the range from the last one, a plain click opens as usual, Escape or a click elsewhere drops the choice. Picked rows are tinted orange (`.is-selected`, `aria-selected`).
- **Drag and drop of rows (points 75–79, 160, A131–A139, A153, A155, A168, A336–A341)** – one set of rules for every window (`modules/documents-dnd.js`: `aim()` says where a drop lands, `land()` what it does), two ways in with one feel: a row starts to move after a few px (a finger after a short hold), an orange label with the name or "3 Dokumente" hangs on the pointer, Escape cancels, near a window body's edge it scrolls. The row or window body a drop would land on turns orange (`.is-drop-target`); while documents or a booking are carried, every other place that takes them is outlined dashed (A336, `html.is-carrying-docs` (bookings) / `is-carrying-move` (folder rows) / `is-carrying-booking` (documents), `modules/dnd.css`); a place that takes nothing shows nothing (the browser's "no drop").
  - **Which engine (decided for point 160):** a **mouse** drags documents and bookings with the browser's own HTML5 drag and drop (`modules/documents-dnd-native.js`) – only that reaches other DocHamster tabs/windows and the desktop; the orange label is its drag image. **Folders** (sorting needs the gaps between rows and the orange line) and **every finger drag** stay on the pointer engine (HTML5 drag and drop does not work with touch). Both call the same `aim()`/`land()`.
  - **Drag sources:** `[data-doc]` rows (all picked rows, A338), `[data-doc-drag="<id>"]` – one document without being a list row (a candidate in a booking window, the head of a detail window via `<x-window :drag-doc :drag-file>`; the preview pans and marks, so it is no handle) – and `[data-booking-drag="<link url>"]` with `data-booking-label` (a booking row, A337). A row may carry `data-doc-file="mime:name:absolute url"` (`Document::dragFile()`): dragged out to the desktop/Explorer it becomes the file (Chrome `DownloadURL`, A340, one document only).
  - **Between tabs (160.4):** `dataTransfer` carries `application/x-dochamster-document` (JSON `{org, ids, trashed}`) or `application/x-dochamster-booking` (JSON `{org, url}`), plus `text/uri-list`/`text/plain` (the addresses) and the type `application/x-dochamster-org-<org id>` – dragover can read types but not data, so a tab of another organisation shows "no drop" at once; `[data-dnd][data-org]` names this page's organisation. The server checks again (documents and bookings of another organisation are not found). A booking address from another tab is used only if it is this app's `/bank/transactions/…/link`. When the drop happened in another tab, the source tab reloads its folder and Bank windows.
  - Documents → a folder row (also in another window) or the free space of a folder window: moved there; → the Papierkorb row or window: trashed; from the Papierkorb onto a folder: restored into it. All picked rows go together.
  - Folders (`data-drag-folder`, only normal folders – "Dokumente allgemein" and the Papierkorb never move) → the middle half of another folder row: into it; the upper or lower quarter or the gap: a new place in the same list (the orange line `.pick-drop`); never into itself or below itself (no highlight; the row carries `data-path`, `data-depth`, `data-height`); too deep: no highlight and a hint on drop; → the Papierkorb row: deleted with its content after a confirm.
  - Every result is a toast from the server's answer, moves with **"Rückgängig"**; then the folder and Papierkorb windows reload their body. Addresses and texts come from one hidden `[data-dnd]` element in the layout (only the routes this person may use).
  - Documents → an element with `data-doc-drop="<POST url>"` (a booking row in a Bank account window, A269; the booking card of a booking window, 160.2): the ids are posted as `ids[]`, the answer's `message` is the toast ("Verknüpft") with **"Rückgängig"** when the answer has `undo: {url, ids}` (A339: removes only the links this drop made), then `DocHamster.emit('bank:changed')` reloads the Bank windows. Any module may offer such rows. A booking (`data-booking-drag`) → a document row, a candidate or a detail window (head or body): the same link (A337).
  - **Drag row (160.5, points 192, 193):** a row that is there to be dragged has no grip: `li.pick-row.drag-row[data-doc-drag]` – **the whole row drags**. The way for finger and keyboard is an icon button with the same action at the row end (`.row-actions` > `control-button`, tooltip, e.g. `link` "Mit dieser Buchung verknüpfen"). Hint text above the list says where to drag. Used by "Belegvorschläge" (`bank/suggestions.blade.php`), the window beside a booking: at most ten documents, best score first, each with its percentage, none under 20 % (A367); the booking window opens it, or Dokumente ("Ordner daneben öffnen", `layout-columns`), as its one window to the right – an ordinary `data-window` link, so one replaces the other (A371).
- **Row amount (A267, A309)** – `<span class="row-amount">−340,00 EUR</span>` at the right end of a row (after an optional status `pill`) or in a `prop-value`: figures line up (tabular), never wraps. **Every amount carries its sign** (`Transaction::signed()`): money coming in `row-amount is-income` green with "+", money going out in text colour with "−" (U+2212) – never red. A booking row's icon shows the kind of booking (A312: `credit-card` card, `arrows-left-right` transfer, `calendar-repeat` direct debit/standing order, `percentage` fee/interest, `building-bank` own transfer, `cash` cash, `circle` other), the bank's type and a pending state as small `pill`s.
- **Sum line (A310)** – `<p class="amount-summary"><span>Eingänge <span class="row-amount is-income">+…</span></span><span>Ausgänge <span class="row-amount">−…</span></span><span>Saldo <span class="row-amount">…</span></span></p>` above a list of bookings, for exactly what the list shows (filters, period).
- **Eintragszeile (entry row, point 190)** – `<form class="cash-entry" data-bank-action>` above a list: a small create form whose `.field`s and `fieldset`s (e.g. an Umschalter als Auswahl) stand side by side and wrap in a narrow window, the main button (symbol + text) at the end; `.cash-entry-text` takes the remaining room. Saves on submit, the window reloads with the new row. Used by the Bargeldkasse (`bank/_cash-fields.blade.php`); its rows typed by hand carry row actions – pencil (Bearbeiten as a dialog) and a red trash (Löschen with a confirm dialog) –, imported bookings none. **PO 2026-11-16:** every label on one line and every control on one line – fields, Umschalter and the button are 40 px (`button-small`); the row is top-aligned, the button sits level with the fields.
- **Filter as Umschalter in the toolbar (A304, A311, 188.3)** – a window's main filter stands in its toolbar (slot `actions`): `<div class="switcher win-wide-only" data-switch-static>` of `<a aria-pressed>` links (counts as small `pill`s), one click reloads only this window (bank: `data-bank-filter`); in a narrow window the same as `<div class="dropdown win-narrow-only">` with an `icon-button` and `menu-item`s. The search panel keeps only the rarer fields; its run button is the magnifier with tooltip "Suchen".
- **Suchkopf and filter chips (points 6, 105)** – above search results `<div class="search-head"><h2>12 Dokumente gefunden</h2><a class="control-button" …><x-icon name="x" /></a></div>` (count, X closes the search), then `<div class="filter-chips">` of `<span class="filter-chip">Label<button type="button" class="control-button" aria-label="…"><x-icon name="x" /></button></span>`: one chip per active filter, its X drops just that one.
- **Suchzeile** – `<span class="search-row">` puts small fields side by side (von – bis, a select and a field) and wraps when narrow.
- **Blättern** – `<nav class="pager" aria-label="Seiten">` with the links "Zurück" / "Weiter" below a paged list, each only when that page exists (`bank/_pages.blade.php`).
- **Notiz-Zeichen (A319)** – `<span class="row-note" data-tooltip="…" aria-label="Notiz: …"><x-icon name="note" /></span>` in a row whose record has a note; the note is the tooltip.
- **Red row action** – `control-button control-danger` inside `.row-actions`: frameless like the others, red on hover (Papierkorb, delete).
- **Tag search** – `<input class="tag-search" type="search" data-tag-search>` above the pills in the Tags window; filters while typing.
