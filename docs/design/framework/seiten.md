# UI framework – Ganze Seiten

Whole modules built from the blocks: properties module, statement drop. Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-seiten.html`.

## Building blocks

- **Properties module ("Eigenschaften", A191–A194)** – a module that edits one record's properties has **no save button**: `<form method="post" action="…" data-autosave>`. Every choice saves the moment it changes – `select`, radios (colour, symbol), checkboxes, the own colour (picker closed or a complete `#rrggbb`) – as a JSON POST of the whole form; the answer's `message` is the toast ("Gespeichert."). A **text field** saves only on purpose: it sits in a `.field-addon` with a ✓ button `data-field-save` (`hidden` at first); the ✓ shows as soon as the value differs from the saved one, **Enter or ✓ saves**, then it hides again; leaving the field keeps the typed text and the ✓; **Escape** restores the saved value. Until then other saves send that field's saved value. A refused save (422) shows the error toast and a red field frame. After a save the framework emits `DocHamster.on('properties:saved', ({ form, json }) => …)`; the module uses it to update its record **everywhere at once** (rows in other windows, the module's head and strip – folders: name, colour classes, symbol; a move reloads the folder windows; the controller answers the data, e.g. `folder: {id, name, rowClass, icon (svg), moved}`). **Without JavaScript** the form still posts: keep `<noscript><button type="submit">Speichern</button></noscript>`. Folder and Papierkorb properties are the reference (`folders/index.blade.php`, `folders/trash.blade.php`). **Rule (point 170):** a value that makes sense alone saves at once (this pattern, Click-to-edit, or Fenstertitel umbenennen); a save button only where several fields make sense only together – create forms, dialogs, a change that needs the password – and then normal-sized, never `button-small`. Feedback: the toast "Gespeichert." (or the field's ✓ hiding); errors at the field (red frame) plus the error toast.
- **Statement drop (Bank module, A267)** – a row `li[data-statement-drop="<upload url>"][data-account][data-upload-label]` or a window `<x-window data-statement-drop data-account data-drop-label>` takes one CSV/Excel file dragged from the computer (`modules/bank.js`): the row turns into the field "Loslassen zum Importieren in „X“" (same look as a folder row, the CSS rule covers every `.pick-row[data-upload-label]`), the window body shows the label on top. The server either imports at once (toast, windows reload) or answers `{columns}`, which opens as a window to the right.
