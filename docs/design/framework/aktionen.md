# UI framework – Aktionen

Buttons, Knopfgruppe, Umschalter, dropdowns and menus. Part of the UI framework: read the core rules in [`../FRAMEWORK.md`](../FRAMEWORK.md) first. Live samples: `/design/styleguide-aktionen.html`.

## Buttons

Every `<button>` and `.button` is a button by default. Do not reuse its look for anything else. **This table is the whole set (point 243, A433): no further variants, no local sizes, no inline styles.** `scripts/check-ui.php` (CI, `composer check-ui`) rejects classes no stylesheet knows and every `style` attribute (the CSP `style-src 'self'` blocks them in the browser; computed values are set from script). it also counts framework classes (`css/core`) the styleguide does not show (`--list` names them, goal 0; pure script states are on its short allowlist).

| Kind | Markup | When |
|------|--------|------|
| Main | `<button>` | The one main action of an area |
| Side | `<button class="button-quiet">` | Cancel and side actions; grey fill, same shadow as the others, **no frame** (PO 2026-11-16: never a white button with a frame) |
| Delete | `<button class="button-danger">` | Delete only |
| Small | add `button-small` | 40 px instead of 48 px, e.g. in list rows |
| Icon | `<button class="icon-button" aria-label="…" data-tooltip="…">` | Square, icon only, always with tooltip; grey fill with shadow like Normal, no frame |
| File | `<label class="button button-small file-button" data-tooltip="…"><input class="visually-hidden" type="file" …><x-icon name="upload" />Hochladen</label>` | Picks files and starts at once (point 182, Posteingang head); focus ring on the label, `is-busy` (faded, spinning symbol) while sending |
| Link | `<button type="button" class="button-link" data-tooltip="…">` + small symbol + text | An action inside running text or a subline (point 165.6: "lesen als Tag, Monat, Jahr"); orange text, no frame, underlined on hover |
| Group | `<div class="button-group" role="group" aria-label="…">` around buttons | **Actions** side by side (zoom bar, editor toolbar); rounded only outside, a toggled one `aria-pressed="true"`. A group used as a **choice** is always the Umschalter (point 188.3) |
| Knopfgruppe | in a window toolbar: a single `.icon-button`, or `<span class="switcher is-actions" role="group" aria-label="…">` around buttons/links without button classes | **Actions** in a window toolbar (point 200): the Umschalter's grey rail, no frame, hover a darker grey, never the chosen look. Actions that belong together share one rail ("Neues Dokument" + "Neuer Ordner"); the ⋯ menu stands alone. The Umschalter itself is unchanged |
| Umschalter | `<span class="switcher" role="group" aria-label="…">` around `<button>`s or `<a>`s with `aria-pressed` (no button classes) | The horizontal choice (point 188.2, variant B): one grey rail (`--surface`, 10 px corners, 3 px padding, 2 px gap) with text or icon segments; the chosen one a raised white segment in the marked look (`--mark-surface` / `--mark-shadow`, icon orange); hover a slightly darker grey. Narrow (188.4): the rail fills the width; when it still does not fit, `core/button-choice.js` shows a small `select` in its place (`.is-tight` + `.switcher-select`, measured on every size change of its parent like the bank toolbar) – `data-switch-static` = never (the module has its own narrow form, e.g. a dropdown) **Symbols (PO 2026-11-16):** every option shows its symbol and its text where a fitting symbol exists (Liste, Kacheln, Kalender, property types, roles, Einnahme/Ausgabe …); periods and Alle/Ja/Nein stay text only. **Too narrow:** our own dropdown takes the rail's place (`.dropdown.switcher-select`, built by `core/button-choice.js`: `.switcher-select-button` with the chosen symbol, name and `.switcher-select-chevron`, the panel lists `menu-item`s with their symbols, the chosen one `aria-checked`) – never the browser's select. |
| Quiet link | `<button type="button" class="button-link is-quiet">` | A side action that should not draw the eye ("Zurücksetzen" in the search panel, 187.4): muted text, orange on hover |
| Quiet red link | `<button type="button" class="button-link is-danger" data-dialog-open="…">` | A destructive side action inside an open row ("Zugang entfernen", point 218): red text, no frame; it always opens a confirm dialog with the red delete button |
| Aktionszeile | `<div class="actions">` around buttons (forms inside allowed) | One row of actions below content (point 243, A432): **all the small size** (40 px, icon buttons 40 × 40) whatever their own class, one even gap, wraps when narrow; **at most one** filled main button, the rest `button-quiet` / `button-danger` / `icon-button` (checked by `scripts/check-ui.php`) |
| Control | `<button type="button" class="control-button" aria-label="…" data-tooltip="…">` | Window controls only (minimise ‹ – one term, A218 –, unfold ›, maximise, close): **no frame**, icon in text colour, orange on hover; 36 px in window heads. The menu arrow is its 48 px flavour (points 70, A116) |

48 px high (small 40 px), 10 px corners (icon buttons too, link or button), semi-bold, no letter spacing, light shadow that presses in on click, orange focus ring for the keyboard, faded when disabled. A link stays underlined text and never looks like a button.

**Cursor (A192):** everything clickable shows the hand – one central rule in `css/core/buttons.css` (`:where(…)`, zero specificity): buttons, `.control-button`, icon buttons, row actions, menu entries, links (also whole rows), `summary`, tabs, strips, colour swatches, icon choices, chips, checkbox/radio labels and `select`. Drag edges show `col-resize`, things that move `grab`; disabled things `not-allowed`. Don't set `cursor: pointer` per module.

## Building blocks

- **Umschalter als Auswahl (Umschalter as a choice, points 135, 188, A283/A284)** – instead of radios or a select with "egal": `<span class="button-choice" data-choice><input type="hidden" name="match" value=""><span class="switcher" role="group" aria-label="…">` with segments `<button type="button" data-value="…">` (`aria-pressed`); the "Alle" / default option is `data-value=""` and comes first. A click sets the hidden field and `aria-pressed` and sends `change` from the field (`core/button-choice.js`, delegated); `data-choice-toggle` lets a second click on the pressed button set it back to "". After code changed the fields, `DocHamster.syncChoices(root)` makes the buttons follow. Blade in the documents search: `documents/_search-choice.blade.php`.
- **Dropdown** – `<div class="dropdown"><button type="button" class="icon-button" aria-expanded="false">…</button><div class="dropdown-panel" hidden>…</div></div>`. Works in every window, also in windows loaded later and several side by side; a click outside, on an entry or Escape closes it. A tag filter (`form.dropdown[data-kind="filter"]`) only filters the list of its own window. The open panel hangs fixed below its button and opens to the bottom right (left edges flush, point 158.2); only without room on the right it turns right-flush, and upwards when there is more room above. In row actions the toggle is a frameless `control-button` instead (A360); the row actions stay visible while its panel is open. Every entry shows a visible hover and keyboard focus; the chosen entry has the marked look (point 158), follows scrolling and resizing, and scrolls when longer than the space.
- **"⋯" menu** – `<x-more-menu><a class="menu-item" href="…" data-window><x-icon name="pencil" /><span>Bearbeiten</span></a>…</x-more-menu>`: entries with icon and text; an entry with `data-window` opens its target as a window on the right. Fits in a window's `actions`. A line `<hr class="menu-separator">` sets entries apart; a destructive entry (Löschen) is `menu-item menu-danger`, red, always last below a separator. Entries never wrap; a menu is as wide as its longest entry. **A module's own ⋯ menu** is not written by the module: `<x-window>` draws it at the right end of the toolbar; the module puts its entries in the slot `menu`. **A351:** the framework's first entry is "Auf Home anheften" (`pin`, `[data-pin-home="<dashboard.pins.store>"]`, `core/window-pin.js`): it posts the window's address (as a path), title and symbol to Home's Schnellzugriff, toasts the answer and emits `dashboard:pinned`; a separator follows when the module has entries. Only the Home window itself (`kind="dashboard"`) and pages without sign-in have no such entry – and with no module entries either, no ⋯ button (A200). A separator with nothing visible below it hides.
- **Column menu ⋮ (points 65–67)** – a column inside a module (e.g. a notes column) puts all its actions into `<x-more-menu class="kanban-menu" icon="dots-vertical" label="Spalte">` at the right of its head – no loose buttons below or beside the column. The button shows only while the column is hovered or the menu has focus or is open; on touch devices (`hover: none`) always. Order: add ("Notiz hinzufügen" – the only way to add a note, point 177), rename (`data-focus="<edit-in-place id>"` starts click-to-edit), colour dialogs (`<x-color-picker>`), the width as a Knopfgruppe als Auswahl below a `.dropdown-title` "Breite" (Schmal | Normal | Breit = 14 / 18 / 26 rem, saved at once; point 179), move left/right (`disabled` at the ends; `.menu-item:disabled` is greyed), a `.dropdown-title` group of `role="menuitemradio"` entries (sorting), bulk actions, and the red delete entry last. Column colour: class `has-color` + `c-rrggbb` tints the column (no inline styles).
- **Choice stack (A286)** – `<div class="menu-stack">` of `menu-item` buttons in a dialog, each in its own form: one click saves. A last entry that needs text ("Anderer Grund") opens a `field-addon` with ✓ (Enter or ✓ saves).
- **Unterstützen-Link** – `<a class="list-entry support-link" …><x-icon name="heart" /><span>…</span></a>`: the last, quiet entry of the Einstellungen menu window, red heart.
