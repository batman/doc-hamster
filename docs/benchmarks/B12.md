# B12 receipt-pack benchmark (procedure for P4-2)

PLAN §5.2 / PLAN-REVIEW B12: the receipt-pack PDF renderer passes if a
**synthetic 150-page pack** builds in **≤ 60 s** using **≤ 256 MB** of PHP
memory on the minimum hardware (D-010), with the PDF at **≤ 50 MB**.
Renderer proposal: Dompdf; if it fails the benchmark, another pure-PHP
library with an allowed license (D-022) — never headless Chromium.

## Corpus

Generate it (content is random and fake, safe for the public repo):

```sh
docker compose exec app php scripts/b12-corpus.php --pages=150
```

Output (default `storage/app/benchmark-b12/`, git-ignored): `receipt-001.jpg`
… `receipt-150.jpg` plus `manifest.json` (file, merchant, amount, currency,
date per page). `--seed` makes the corpus reproducible; `--out` overrides
the directory.

## Running the benchmark (P4-2)

1. Generate the corpus above.
2. Render it with the candidate renderer into one PDF (cover + overview +
   one page per receipt, PLAN §10.1).
3. Measure wall time (`time`), peak PHP memory (`memory_get_peak_usage`),
   and PDF file size.
4. Pass = ≤ 60 s, ≤ 256 MB, PDF ≤ 50 MB. Record the numbers in the P4-2 PR.

Photos are pre-scaled to ~1600 px / JPEG 80 by a `local` job before
rendering (PLAN §5.2); the corpus pages stand in for that input.
